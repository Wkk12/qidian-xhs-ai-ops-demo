## 总体目标与范围

### 最终交付

把当前纯前端 Demo 升级为可在机构本地电脑运行的 AI 小红书运营平台：完成账号分析、七天连续内容规划、文案与配图生成、历史文案查重、人工编辑、定时发布、数据复盘和后续六天滚动优化。

### 核心闭环

账号定位 → 生成七天连贯大纲 → 生成文案与配图 → 文案库查重 → 人工编辑确认 → 定时发布 → 读取运营数据 → 每日复盘 → 优化“今天 + 6 天”后续大纲。

### 已确认规则

- 默认生成一周内容，用户可调整天数、每天条数、每条图片数量、图片类型和主题。
- 七天内容必须使用同一条内容主线，后一天承接前一天，不能随机拼凑。
- 新内容必须与历史文案库逐篇比较，相似度达到 60% 时自动退回重写。
- 所有文案和图片均允许用户手动编辑、替换、删除或重新生成。
- 支持人工确认后定时发布，也可在完成新手引导后选择无人值守模式。
- 每日根据账号数据与行业热点复盘，并滚动优化后续六天内容。
- 密钥只保存在客户本机，仓库、日志和前端页面不得出现明文密钥。

### V2 不做

- 不绕过小红书登录、风控、验证码或平台限制。
- 不承诺无法从 MCP 或平台合法取得的指标。
- 不在未经确认的情况下自动发布高风险或疑似违规内容。
- 不把真实账号 Cookie、API Key 或用户素材上传到公共仓库。

### 前置依赖

- 明确小红书 MCP 的登录、发布、定时发布、内容查询和数据读取接口能力。
- 准备 DeepSeek API Key，并确认所用模型、费用和调用限额。
- 准备 QweAPI Key，并确认 `img2.5` 的实际模型名称、接口协议、图片规格和商用许可。
- 确认首批客户电脑主要为 Windows 还是 macOS。
- 确认仓库可见性、真实数据保存周期和机构多账号需求。

## 技术方案基线

- **桌面操作页面**：Vue 3 + Element Plus，沿用当前 A“珍珠影棚”视觉方案。
- **本地业务服务**：Java + Spring Boot + MyBatis，负责账号、内容、任务、查重和数据汇总。
- **本地数据**：首版优先 SQLite，减少小白用户安装数据库的成本；如确定需要多账号或多人协作，再评估 MySQL。
- **任务调度**：服务端持久化任务 + 可恢复调度，电脑重启后自动补载未执行任务。
- **模型适配**：DeepSeek 与 QweAPI 分别封装适配器，业务层不直接依赖某个具体模型。
- **发布适配**：小红书 MCP 作为独立适配层，平台升级时只替换连接实现。
- **密钥安全**：本机系统凭据库或加密配置文件保存，页面仅显示掩码。
- **安装交付**：一键检测与安装脚本、桌面快捷方式、开机自启、故障诊断和卸载入口。

- **接口清单**：先用 `api-doc-gen` 生成接口文档与 OpenAPI，再进入编码。
- **实现步骤**：
  - [ ] 逐项实测 MCP 登录、账号主页读取、发布、内容查询与数据读取能力。
  - [ ] 核对 DeepSeek 和 QweAPI 请求格式、模型名称、限额、错误码与重试规则。
  - [ ] 确认单账号/多账号、Windows/macOS、公开/私有部署范围。
  - [ ] 输出系统架构、数据流和安全边界图。
- **涉及文件**：`docs/requirements/`、`docs/api/`、`docs/architecture/`。
- **验收点**：每个外部能力都有可运行的最小调用验证和失败提示。

- **状态 / 日志**：☐ 未开始。

- **数据模型**：系统配置、安装状态、运行日志、任务锁。
- **接口清单**：健康检查、环境扫描、依赖安装状态、服务启停。
- **实现步骤**：
  - [ ] 建立 Vue 前端、Spring Boot 服务和 SQLite 数据层。
  - [ ] 检测操作系统、端口、磁盘空间、网络、运行时和 MCP 文件。
  - [ ] 提供逐步安装进度、失败原因和一键重试。
  - [ ] 建立脱敏日志和本地备份目录。
- **涉及文件**：`web/`、`server/`、`installer/`、`sql/`。
- **验收点**：全新测试电脑按引导完成安装，桌面快捷方式可启动，健康检查全绿。
- **待确认**：首发系统版本和最低硬件要求。
- **状态 / 日志**：☐ 未开始。

### P2 · 账号授权、模型配置与安全存储

- **目标**：小白用户可以按向导连接小红书、DeepSeek 和 QweAPI。
- **数据模型**：账号授权、模型配置、连接检测记录；密钥只保存密文或系统凭据引用。
- **接口清单**：连接检测、授权状态、密钥保存/替换/删除、模型可用性测试。
- **实现步骤**：
  - [ ] 制作三步式首次连接向导。
  - [ ] 页面只展示密钥掩码，不回传完整值。
  - [ ] 区分“未配置、检测中、可用、过期、限额不足、连接失败”。
  - [ ] 提供重新授权和故障修复指引。
- **涉及文件**：`server/integration/`、`web/views/settings/`、`installer/`。
- **验收点**：断网、错误 Key、过期授权和服务未启动均能给出大白话提示。
- **待确认**：密钥由机构自行申请还是交付人员协助申请。
- **状态 / 日志**：☐ 未开始。

### P3 · 账号定位、文案库与 60% 查重门禁

- **目标**：读取账号历史内容，形成账号定位，并建立不可重复的本地文案资产库。
- **数据模型**：账号画像、历史文章、文本分段、主题标签、向量/指纹、查重报告。
- **接口清单**：同步历史文章、生成账号定位、搜索文案、提交查重、查看查重报告。
- **实现步骤**：
  - [ ] 抽取人设、受众、内容支柱、语气、卖点和转化目标。
  - [ ] 同步历史文案与系统生成文案，建立统一文案库。
  - [ ] 比较标题、结构、核心观点和表达方式，给出最高相似文章与具体重复位置。
  - [ ] 达到 60% 自动重写，最多三次；仍不通过则交给人工处理。
- **涉及文件**：`server/account/`、`server/content-library/`、`server/similarity/`、`web/views/library/`。
- **验收点**：重复样本必定被拦截；通过样本能追溯比较对象与分数。
- **待确认**：相似度算法最终采用向量、关键词加权还是混合评分。
- **状态 / 日志**：☐ 未开始。

### P4 · 七天连续运营大纲引擎

- **目标**：先形成一条七天内容主线，再为每天分配承上启下的内容任务。
- **数据模型**：周计划、每日节点、内容目标、前后依赖、转化阶段、版本记录。
- **接口清单**：生成大纲、编辑节点、锁定节点、重排计划、连贯性检查、版本回滚。
- **实现步骤**：
  - [ ] 根据账号定位、目标和内容支柱生成周主题。
  - [ ] 将七天分为痛点、认知、方法、延伸、证明、价值和转化。
  - [ ] 每个节点保存“承接什么、提供什么、为下一天留下什么”。
  - [ ] 支持用户编辑后重新检查连续性，而不是整周无条件重生成。
- **涉及文件**：`server/outline/`、`web/views/outline/`。
- **验收点**：随机抽查任意连续三天，主题、观点和行动引导能够自然衔接。
- **待确认**：默认七阶段是否允许机构自定义模板。
- **状态 / 日志**：☐ 未开始。

### P5 · 内容工坊、文案生成、配图生成与编辑

- **目标**：根据锁定大纲批量生成内容，并让用户修改任何文字和图片。
- **数据模型**：文章、图片任务、素材、版本、人工修改记录、质量检查结果。
- **接口清单**：批量生成、单篇重生成、保存编辑、生成/替换图片、预览、质量检查。
- **实现步骤**：
  - [ ] 支持天数、每天条数、图片数量、图片类型、主题和风格选择。
  - [ ] DeepSeek 生成标题、正文、标签、封面字和图片提示词。
  - [ ] QweAPI `img2.5` 生成美妆、穿搭、课堂和案例风格配图。
  - [ ] 每次生成先通过文案库查重，再进入可编辑草稿。
  - [ ] 实现文案、图片、顺序、发布时间和标签的逐项编辑与版本恢复。
- **涉及文件**：`server/generation/`、`server/assets/`、`web/views/studio/`。
- **验收点**：生成七天内容后，任意一篇可编辑、替图、重生成并保存；不通过查重的内容不能进入排期。
- **待确认**：图片是否需要人物一致性、机构 Logo、固定模特或学员授权管理。
- **状态 / 日志**：☐ 未开始。

### P6 · 发布队列、定时任务与小红书 MCP 发布

- **目标**：人工确认后的内容可靠进入队列，并在目标时间通过 MCP 发布。
- **数据模型**：发布任务、任务状态、重试记录、发布结果、平台内容标识。
- **接口清单**：创建排期、确认发布、取消排期、立即发布、查看状态、失败重试。
- **实现步骤**：
  - [ ] 建立可持久化的发布状态机，避免重复发布。
  - [ ] 发布前 15 分钟检查账号授权、文案门禁、图片文件和网络。
  - [ ] 调用 MCP 并记录可追溯结果，失败时暂停而不是盲目连续重试。
  - [ ] 电脑关机或重启后恢复未完成任务，并提示错过的发布时间。
- **涉及文件**：`server/publishing/`、`server/scheduler/`、`web/views/schedule/`。
- **验收点**：定时、立即、失败、重启恢复和防重复五条流程全部通过。
- **待确认**：MCP 是否原生支持定时；若不支持，由本地调度器到点调用。
- **状态 / 日志**：☐ 未开始。

### P7 · 数据监控、每日复盘与滚动六天优化

- **目标**：每天把运营数据转成后续内容修改建议，形成真正闭环。
- **数据模型**：指标快照、文章表现、线索、复盘报告、建议、计划变更记录。
- **接口清单**：同步指标、生成日报、查看内容表现、生成建议、应用/拒绝建议。
- **实现步骤**：
  - [ ] 同步 MCP 可取得的曝光、互动、涨粉和内容表现数据。
  - [ ] 用户手动补录咨询、到店、成交和营收数据。
  - [ ] 结合行业热点与账号定位生成每日复盘。
  - [ ] 只调整未发布内容，滚动维护“今天 + 6 天”计划。
  - [ ] 所有 AI 修改先展示差异，用户确认后应用。
- **涉及文件**：`server/analytics/`、`server/review/`、`web/views/analytics/`。
- **验收点**：一篇内容发布后，次日数据可进入复盘并生成可接受或拒绝的后续调整建议。
- **待确认**：热点数据的合法来源，以及咨询/营收数据的录入方式。
- **状态 / 日志**：☐ 未开始。

### P8 · 小白引导、一键安装、验收与交付

- **目标**：没有开发环境的机构员工也能安装、完成首篇内容并理解日常操作。
- **数据模型**：引导进度、检测报告、版本号、升级记录。
- **接口清单**：引导状态、诊断报告、备份恢复、版本检查。
- **实现步骤**：
  - [ ] 制作具有终端过程感的一键安装器，但每一步都有清晰中文说明。
  - [ ] 自动安装运行环境、创建快捷方式、注册服务和配置开机自启。
  - [ ] 首次引导完成连接账号、生成简单主题、编辑、确认和测试发布。
  - [ ] 提供一键诊断包、备份恢复、升级和安全卸载。
  - [ ] 编写面向小白的图文使用指南和常见问题。
- **涉及文件**：`installer/`、`docs/user-guide/`、`web/views/onboarding/`。
- **验收点**：全新电脑由非技术人员独立完成安装并成功发布一篇测试内容。
- **待确认**：安装包签名、自动更新服务器和远程售后方式。
- **状态 / 日志**：☐ 未开始。

## 全程质量与安全验收

- 任何密钥、Cookie、二维码和用户内容都不得进入代码仓库或普通日志。
- 所有 AI 输出必须记录模型、提示词版本、生成时间和人工修改历史。
- 60% 相似度门禁必须在排期和发布两个入口重复校验。
- 定时任务必须具备幂等、防重复、失败暂停和重启恢复能力。
- 数据复盘只能自动修改未发布草稿，且默认需要人工确认。
- 页面必须适配常见笔记本分辨率，并提供大白话错误提示。
- 每阶段完成后执行定向测试、演示主流程并等待用户确认。
