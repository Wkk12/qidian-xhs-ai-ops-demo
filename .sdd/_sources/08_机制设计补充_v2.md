## 一、数据抓取机制（修订）

> **落地状态**：✅ **抓取部分已完成**（定时 09:30/20:30 + 手动触发 + 落库 `trends` 表 + 内容工坊热榜区）；AI 理解/关键词建议待做

### 你的要求
- 每天**自动抓取 2 次**：早一次、晚一次
- 增加**手动触发**（抓行业内容）
- **问题**：是"AI 决定抓什么"还是"机制决定抓什么、AI 只处理"？

### 建议方案：**机制决定抓什么，AI 负责理解；AI 可反哺调整关键词**

```
【机制层：稳定、可预测、可控】
  关键词表（三类来源）
    ├─ 行业词库（预设，如：化妆教程/底妆/眼妆/通勤妆/学员改造/化妆学校）
    ├─ 自己笔记的高频标签（自动统计）
    └─ 对标账号常用话题
  抓取频率：每天 09:30 / 20:30 各一次 + 手动触发按钮
  抓取量：每个关键词取前 20 条（按热度排序）
  防风控：词间间隔 3–5 秒；同一次任务总请求 ≤ 100
        ↓
【AI 层：理解、归纳、判断】
  ① 把抓回来的原始数据「去重 + 归类」
  ② 输出《本期行业热点摘要》：这周在火什么题材、什么标题句式、什么封面
  ③ 判断「哪些热点与本账号定位匹配」（不匹配的丢掉，避免跑偏）
  ④ 给出建议：新增/停用哪些关键词
        ↓
【回写机制层】
  AI 建议的关键词 → 人工确认 → 下一轮抓取生效
```

**为什么这样分**（回答你的问题）：
| 让 AI 决定抓什么 | 机制决定 + AI 处理（**推荐**）|
|---|---|
| 抓取行为不可预测，可能触发风控 | 请求量、频率完全可控 ✅ |
| 结果不稳定，今天抓 A 明天抓 B | 可复现，问题好排查 ✅ |
| AI 每次调用都花钱（决策也要钱）| AI 只花在"理解"上，省钱 ✅ |
| 关键词漂移，容易跑出行业 | 关键词表可人工审 ✅ |

> 一句话：**抓取 = 机械动作（机制干）；选材 = 判断动作（AI 干）；关键词 = AI 建议、人工拍板。**

**状态**：抓取通道 ✅ 已通 ｜ 定时+手动触发+落库 ❌ 待做

## 二、评论区回复机制（修订）

> **落地状态**：⬜ 待开发（通知通道 ✅ 已通并能拿评论原文）

### 你的要求
- 触发频率：**每 5 分钟一次**
- **监控不用 AI**（用规则）
- **回复必须用 AI**

### 方案：规则监控 + AI 生成（分工明确）

```
【规则层 · 每 5 分钟一次，不花 AI 钱】
  拉 /notifications/list（新评论）
     ↓
  过滤判断（纯代码规则）：
    ① 黑名单命中？          → 跳过，只记录
    ② 已经回复过？          → 跳过（去重，防重复回）
    ③ 是表情/纯符号？        → 跳过或简回
    ④ 命中知识库关键词？     → 进入"待回复队列"
    ⑤ 未命中                → 进入"人工处理队列"（回兜底话术或只提醒）
        ↓
【AI 层 · 只对进入队列的评论调用】
  输入 = 人设卡 + 命中的知识库条目 + 评论原文 + 最近对话上下文
  输出 = 30–60 字回复（带人设、口语化）
        ↓
【合规层 · 规则检查】
  绝对化用语 / 疗效承诺 / 私下交易引导 → 拦截转人工
        ↓
【发布层】
  调用 /notifications/reply 发布 → 写入回复记录（可查/可改/可撤回）
```

**关键点**：
- **5 分钟轮询是纯规则**（一次 HTTP 请求，零 AI 成本）
- **AI 只被"命中知识库的评论"唤醒** —— 大部分评论不会触发 AI，成本极低
- 实测 `notifications/list` 已能拿到：**评论人、评论原文（如"怎么联系"）、评论ID、笔记ID + xsec_token** → 回复所需参数**齐了** ✅

**状态**：通知通道 ✅ ｜ 轮询+知识库+回复链路 ❌

## 三、内容生成的「四个参考系」

> **落地状态**：⚠️ 部分（① 计划表 ✅；② 数据层 ✅ 热榜已落库；③④ 待做）（你的核心设计）

### 参考系 ①：**运营计划表**（长期任务清单 / 目录）⭐ 新增
- 性质：**账号的"宪法"**，定义"这个账号长期要做什么、面向谁、讲哪些主题"
- 内容：账号定位、目标人群、内容支柱（4–6 个主题方向）、发布节奏、转化目标
- 作用：**在用户没有干预时，内容方向就跟着它走**（你说的"跟计划表走"）
- 详见第四节

### 参考系 ②：**抓取的信息**（外部信号）
| 子项 | 用途 |
|---|---|
| 行业热点 | 知道现在什么在火（题材/句式/封面） |
| **自己账号的历史数据** | **评估过往哪类内容效果好 → 往数据好的方向做** |
| **同行数据** | 对标账号哪篇文章数据好 → 作为参考（不抄，过查重） |

### 参考系 ③：**用户输入**（权重最高）⭐
- 位置：策略沟通输入框 / 每条内容旁输入框
- **权重规则（建议）**：
  ```
  用户显式指定（"这周主推暑期班"） → 权重 0.5（最高）
  用户否定（"不要硬广"）          → 硬性排除（不是权重，是过滤）
  运营计划表                       → 0.3（默认基线）
  热点 + 历史数据                  → 0.2（锦上添花）
  ```
> **冲突处理**：**用户指令 > 计划表 > 数据/热点**。
> 例：计划表说本周做"工具入门"，但用户输入"这周主推暑期班" → **以用户为准**，同时提示"已偏离本周计划，是否同步调整计划表？"

### 参考系 ④：**AI 记忆文件** —— 需不需要？（回答你的疑问）

**我的判断：需要一个"记忆层"，但不能只靠"每天写的内容 + 计划表"。**

**理由**：这两样只记录了**"做过什么"，没记录"为什么改、改哪里"** —— 而后者才是让 AI 越来越懂你的关键。

**建议的三层记忆**：

| 层 | 内容 | 来源 | 现状 |
|---|---|---|---|
| **L1 长期记忆** | 运营计划表（该做什么）| 人工设定 + 滚动调整 | ⚠️ 待建 |
| **L2 事实记忆** | 已发内容 + 每篇的数据表现 | 文案库 + 指标采集 | ✅ 已有（46 篇）|
| **L3 反馈记忆** ⭐ | **用户的每次修改/否决 + 原因** | 编辑记录自动归档 | ❌ **缺这层** |

**L3 怎么工作**：
```
用户把标题从 A 改成 B  →  记录：原句/改后/时间
用户点"重写"并说"太硬广" →  记录：否决原因
用户连续三次否掉某类句式  →  下次生成时自动避开
```
**这就是"越用越懂你"的机制** —— 不需要额外让用户写什么，**自动从操作里学**。

> **结论**：计划表（L1）解决"该做什么"，内容+数据（L2）解决"做得怎么样"，
> **反馈记忆（L3）解决"用户喜欢什么样"** —— 三层齐了才算真正的"记忆文件"。

## 五、内容产出机制（修正版 · 按你的原意）

> **落地状态**：⬜ 待开发（此为内容引擎核心，依赖 DeepSeek Key）

### 5.1 我上次理解错了，这是你的原意

| # | 你的机制 | 说明 |
|---|---|---|
| 1 | **总量就是 7 天** | 每次只做 **7 天**的文章量，不多做 |
| 2 | **用户可选"每天发几条"** | 如每天 1 条 / 2 条 → 决定本次产出总量（7 × N 篇）|
| 3 | **以后每天只生成 1 次** | 生成的是**"第 7 天"那批**，补到队列尾部 |
| 4 | **发送内容跟运营计划表走** | 无用户干预时，方向以计划表为准 |
| 5 | **每天生成前判断是否要跟数据波动调整** | 有波动 → 微调；无异常 → 照计划表走 |

### 5.2 机制：7 天滑动窗口

```
【初始建立】
  用户设定「每天发几条」= N（如 2 条）
  → 按【运营计划表】一次性生成 7 天 × N 篇（如 14 篇）
  → 进入"待审核池"
        ↓
【每天固定动作（只 1 次）】
  ① 拉昨日数据（浏览量/点赞/收藏/涨粉 + 波动判断）
  ② 判断：需要调整吗？
       · 数据正常        → 按计划表继续
       · 某题材突然爆发    → 明天那一批偏向该题材
       · 某题材持续走低    → 明天那一批回避
       · 出现新热点        → 少量穿插（不超过 1 篇）
  ③ 生成「第 7 天」那天的量（N 篇）→ 补进队列尾部
  ④ 窗口前移：最前面那天已发完 → 出窗
        ↓
【结果】永远保持 7 天的内容储备，用户审核有缓冲
```

### 5.3 关键点

| 点 | 说明 |
|---|---|
| **为什么是 7 天** | 7 天 = 一个完整的叙事单元（痛点→方法→案例→转化），也刚好是用户能一次审完的量 |
| **为什么每天只生成 1 次** | 成本可控（每天 1 次 AI 调用）、方向稳定（不会一天一个样）|
| **"跟计划表走"怎么理解** | 计划表是**默认方向**；只有数据出现明显波动（超阈值）时才偏离，且偏离要留痕（记录为什么改）|
| **调整的阈值建议** | 单篇互动 > 账号均值 ×1.5 或 < ×0.5 → 视为"波动"，触发调整判断 |

### 5.4 与"七天叙事"的关系
7 天窗口内依然保持**连贯叙事**：
```
窗口内 D1→D7：痛点 → 工具 → 方法 → 场景 → 案例 → 价值 → 转化
窗口滑动后，新补进来的"第 7 天"接着上一个窗口的结论继续（跨窗承接）
```

**状态**：❌ 待开发（这是内容引擎的核心逻辑）
