## 2. 内容生成决策机制 —— "我该发什么"

### 三层输入（对应需求 M2 的三类输入源）
| 层 | 内容 | 来源 | 状态 |
|---|---|---|---|
| **A. 自己** | 历史 46 篇的**题材分布 + 哪类数据好** | 文案库 + 指标 | ✅数据在，❌未参与决策 |
| **B. 平台** | 近期高互动的题材、标题句式、封面类型 | 热门抓取 | ⚠️通道在，❌未接 |
| **C. 用户** | 「这周主推暑期班」「别太硬广」 | **策略输入框** | ❌未做 |

### 决策算法（建议）
对每个候选题材打分：
```
题材得分 = 0.40 × 自己在题材上的历史表现（相对账号均值）
         + 0.35 × 平台当前热度（同类笔记互动量分位）
         + 0.25 × 用户指定权重（输入框里点名的加分）
```
→ 取 **Top 3 题材** → 组合成**本周主线** → 拆成 7 天节点。

### 七天结构模板（认知 → 信任 → 转化）
| 天 | 角色 | 作用 |
|---|---|---|
| D1 | **痛点共鸣** | 让目标用户觉得"说的就是我" |
| D2 | **工具/认知** | 给出低成本的第一步 |
| D3 | **方法展示** | 秀专业度（最出收藏的一环） |
| D4 | **场景延伸** | 穿搭/场合/人群延展 |
| D5 | **案例证明** | 真实改造成果（信任峰值） |
| D6 | **价值升维** | 讲清课程/服务背后的逻辑 |
| D7 | **行动转化** | 明确下一步（预约诊断/私信咨询） |

**硬约束**：每天必须 **承接前一天的结论**，并**留一个钩子**给下一天（不能随机拼凑）。

**状态**：❌ **整套未实现**（当前工坊显示的是历史内容，不是未来 7 天计划）。

## 3. 我的数据如何反向影响生成方向（反馈闭环）

```
内容发布
   ↓
24 / 48 / 72 小时采集互动数据（点赞·收藏·评论）
   ↓
与【账号近 30 天均值】对比
   ├─ 高于均值 ×1.3  → 标记「成功题材」→ 下轮生成加权 +20%
   ├─ 在 0.7~1.3 之间 → 中性，权重不变
   └─ 低于均值 ×0.7  → 标记「回避题材」→ 下轮生成降权 −30%
   ↓
写回「题材权重表」→ 作为下一轮生成的第 A 层输入
   ↓
下一周内容自动偏向被验证有效的方向
```

### 特别强调一个指标：**收藏率**
```
收藏率 = 收藏数 ÷ 点赞数
```
- 收藏率高 = 用户觉得「这个以后有用」→ 小红书最重的分发信号
- **建议把收藏率作为题材成功与否的第一判据**（比点赞更可信）

**状态**：❌ 未实现；但 `metrics` 表（每日快照）已建好，是这条闭环的数据基础。

## 4. 对标账号（同行监控）机制

### 怎么确定"对标"
1. **客户手动指定**（最准，如竞品校区账号）
2. **系统自动发现**：搜索行业关键词时，**出现频次最高的作者**（前 20 条笔记里反复出现的账号）
3. 建议每个客户维护 **5–8 个**对标账号

### 盯什么
| 维度 | 说明 |
|---|---|
| **更新频率** | 日更？周更？找出他们的节奏 |
| **爆款题材** | 取他们**互动量前 20%** 的笔记，看题材共性 |
| **发布时间** | 他们的高峰时段（间接反映粉丝活跃时间） |
| **标题句式** | 疑问式 / 数字式 / 结果前置式，哪种多 |
| **互动量级** | 与自己对比（如"他们是你的 8 倍"） |
| **话题标签** | 他们常挂的标签 = 行业流量入口 |

### 怎么用（重点）
- 把对标**爆款标题 + 题材**作为**风格参考**喂给生成模型
- **但不允许直接改写**——所有生成内容仍要过 **60% 查重门禁**
- 输出形式建议："**对标 @XX 近 7 天有 2 篇爆款，题材为『学员改造』，建议纳入下周备选**"

**状态**：⚠️ 搜索通道可用（能搜到账号和笔记），**对标分析逻辑未实现**。

## 5. 数据分析：分析什么、给什么建议

### 5.1 数据可得性（很重要，先说清）
| 指标 | 能否自动拿到 | 说明 |
|---|---|---|
| 点赞 / 收藏 / 评论 / 分享 | ✅ 能 | 笔记详情接口直接给 |
| 自己笔记列表 + 发布时间 | ✅ 能 | |
| 粉丝总数 | ✅ 能 | |
| **浏览量（曝光）** | ⚠️ 不确定 | 个人号接口通常不开放，需实测 |
| **每日涨粉明细** | ❌ 难 | 平台不开放 |
| **私信数 / 咨询数** | ❌ 不能 | 平台不开放 |
| **到店数** | ❌ 不能 | 业务数据，**必须人工录入** |

> **建议**：**私信/咨询/到店三项做「手工填报」**（客户每天花 30 秒填 3 个数字），
> 这样才能算出真正的**转化漏斗**。这是行业里最务实的做法。

### 5.2 分析维度（6 类）
| # | 维度 | 具体分析 |
|---|---|---|
| 1 | **内容表现** | 点赞、收藏、评论、**收藏率**、互动率 |
| 2 | **账号成长** | 粉丝净增、涨粉与发布量的关系 |
| 3 | **发布规律** | **发布时间 × 表现**（找出黄金时段） |
| 4 | **题材表现** | 各题材互动 vs 账号均值 |
| 5 | **竞品对比** | 对标账号的发布频率/爆款题材/互动量级 |
| 6 | **趋势变化** | 近 7 天走势（上升/平台/下滑） |

### 5.3 建议输出示例（这是产品的"灵魂"）
- 「**收藏率最高的 3 篇都是『方法展示』类（平均 12.4%），建议下周主线加大该类型占比**」
- 「**周三 19–21 点发布的笔记，平均点赞是其他时段的 1.8 倍，建议把 D3 排到该时段**」
- 「**『XX 题材』连续 3 篇低于账号均值 30%，建议暂停该方向**」
- 「**对标 @XX 近期爆款集中在『学员改造』，建议下周纳入 2 篇**」
- 「**近 7 天互动量下滑 18%，但收藏率持平 → 属于曝光问题而非内容问题，建议增加话题标签/参与平台活动**」

### 5.4 曲线图
- **已修**：原来的曲线是**写死的假图**，现已改为**每日采集快照驱动**
- 采集方式：点「采集今日数据」→ 抓自己笔记的互动数存快照
- **连续采集 2 天以上**才会出现曲线（当天只有 1 个点）

**状态**：⚠️ 数据源通、曲线已真；**定时采集 + 自动分析 + 建议输出未实现**。

## 6. 评论区回复机制（含"人设"）

### 6.1 整体流程
```
每 5–10 分钟拉一次通知（新评论/提及）
   ↓
① 黑名单检查（命中 → 只提醒人工，不自动回）
   ↓
② 知识库匹配（关键词 + 语义）
   ├─ 命中 → 生成回复（带人设）→ 合规检查 → 发布 → 记录
   └─ 未命中 → 不猜测 → 回「稍等，我让老师/顾问回你」+ 提醒人工
   ↓
③ 全部回复入库：可查、可改、可撤回
```

### 6.2 "人设"怎么加（你问的重点）
**做法是：给模型一张「人设卡」**，每次生成回复时把三样东西一起喂进去：
```
输入 = 人设卡 + 知识库命中条目 + 用户评论原文
```

**人设卡字段**（可在设置页配置）：

| 字段 | 示例 |
|---|---|
| **身份** | 「绮点化妆学校的课程顾问小绮」 |
| **称呼** | 对用户称「宝子」/「同学」 |
| **语气** | 亲切、专业、不油腻、不说教 |
| **回复长度** | 30–60 字（评论区别写小作文） |
| **口头禅** | 「悄悄告诉你」「这个真的有用」 |
| **禁用词** | 绝对化用语（最好/第一/永久）、疗效承诺、私下转账引导 |
| **结尾动作** | 可引导「想了解可以私信我呀」（视客户意愿） |

**示例输出**（同一条知识库内容，带不带人设的差别）：
- ❌ 不带人设：「课程价格是 3980 元，包含 12 课时。」
- ✅ 带人设：「宝子问的课程价格来啦～3980 元含 12 课时，都是小班实操，想了解具体排课可以私信我呀 😊」

### 6.3 合规检查（后置）
自动回复发出前统一过滤：
- 绝对化用语（「最好 / 第一 / 永久」）
- 医疗/疗效承诺（医美类尤其严格）
- 引导私下交易、联系方式
- 政治/敏感话题 → 直接转人工

### 6.4 触发策略（建议）
- **默认**：**只有命中知识库才自动回**，其余一律提醒人工
- 前 3 天建议：**全部先进"待确认"，人工点一次再发**（建立信任后再放开）
- 可设白名单（如只自动回"问价格/问地址"这类高频问题）

**状态**：❌ 未实现（通知通道已通，是一切的起点）。

## 7. 查重门禁机制（60%）

| 项 | 说明 |
|---|---|
| **比对对象** | 文案库全部历史（现已 46 篇，会持续增长） |
| **比对维度** | 标题相似度 + 正文结构 + 核心观点 + 表达方式（加权） |
| **算法建议** | ① **向量相似度**（本地 BGE-M3，免费、离线）② 关键词/文本相似（快）→ 建议**混合**：先粗筛再精算 |
| **触发动作** | ≥60% → **自动退回重写**（最多 3 次）→ 仍不过 → 转人工 |
| **意义** | 平台判定"搬运/重复"会限流，这条是账号安全线 |

**状态**：❌ 算法未实现（比对底库已有）。

## 8. 发布机制

```
内容确认 → 写入发布队列（publish_tasks）
   ↓
服务内置调度器：每分钟扫描到期任务
   ↓
提前 15 分钟预检：登录态 / 查重通过 / 图片文件存在 / 网络
   ├─ 预检不过 → 停发 + 通知用户
   └─ 通过 → 调用发布通道 → 回写结果
   ↓
失败重试：最多 3 次（指数退避）；进程重启后从表中恢复未完成任务
```
**防风控**：同一账号两次发布**间隔 ≥ 30 分钟**；每日发布上限可配置。

**状态**：❌ 未实现（发布通道已验证可用）。
