## 1. 数据抓取规格

### 1.1 抓哪些数据（三类来源）

| 来源 | 抓取字段 | 用途 | 状态 |
|---|---|---|---|
| **行业热榜**（小红书搜索）| 标题、作者、作者ID、点赞、收藏、评论、封面URL、发布时间、关键词 | 找当下在火什么 | ✅ 已实现 |
| **自己账号**（笔记列表）| 标题、类型、点赞、收藏、评论、封面、发布时间 | 评估自己哪类内容好 | ✅ 已实现 |
| **自己账号**（平台数据）| **浏览量、涨粉、首页曝光、平均观看时长**（含每日趋势）| 真实的平台表现 | ✅ 已实现 |
| **对标账号** | 笔记列表 + 互动数据 + 发布时间 | 找行业标准答案 | ⬜ 待做 |

### 1.2 热度排序公式（决定"什么算火"）

```
热度分 = 点赞 × 1.0 + 收藏 × 1.5 + 评论 × 2.0
```

**为什么收藏和评论权重更高**：点赞是随手，收藏代表"以后有用"，评论代表"有话说"——两者更接近真实需求。

### 1.3 关键词来源与占比

| 来源 | 说明 | 建议占比 |
|---|---|---|
| **行业词库**（预设）| 如：化妆教程 / 新手化妆 / 底妆 / 眼妆 / 通勤妆 | 60% |
| **自己笔记的高频标签**（自动统计）| 从已发内容里提取 | 30% |
| **对标账号常用话题** | 从对标笔记里提取 | 10% |

**默认已配置 5 个关键词**，可在页面改（存 `settings.trend_keywords`）。

### 1.4 频率与风控参数

| 参数 | 值 | 说明 |
|---|---|---|
| 自动抓取时段 | **每天 09:30 / 20:30** | 错开平台高峰 |
| 手动触发 | 随时（页面按钮）| — |
| 每关键词抓取量 | **20 条** | 只取前 20（按热度）|
| 关键词间隔 | **3.5 秒** | ✅ **实测：更快会触发 MCP 限流** |
| 单次任务上限 | ≤100 请求 | 5 关键词 × 20 = 100 |
| 去重 | 按 `note_id` 唯一索引 | 重复自动忽略 |

## 2. 内容生成规格 ⭐核心

### 2.1 四类参考值 + 权重表 ★（你问的重点）

**生成一条内容时，AI 同时参考四类输入，各自权重如下：**

| # | 参考系 | **权重** | 具体内容 | 数据来源 |
|---|---|---|---|---|
| ① | **用户输入** | **0.45** ⭐最高 | 策略输入框说的方向（"这周主推暑期班"）| 用户手动填 |
| ② | **运营计划表** | **0.25** | 账号定位 + 内容支柱占比 + 本周主线 | `positioning` + `plans` 表 |
| ③ | **历史好文** | **0.20** | **自己数据好的文章**（选题/标题/结构/发布时间）| 文案库 + 指标 |
| ④ | **行业热榜** | **0.10** | 当下在火的题材、标题句式、封面类型 | `trends` 表 |

**冲突处理优先级（硬规则，不是权重）**：
```
用户显式否定（"不要硬广"）  →  硬性排除，一票否决
用户显式指定（"主推X"）     →  权重 0.45，压过其他三项
其余按权重加权融合
```

**题材评分公式**：
```
题材得分 = 0.45 × 用户指定分 + 0.25 × 计划表契合度 + 0.20 × 自己历史表现分 + 0.10 × 平台热度分
（每项归一到 0–100，得分最高的题材进入本周主线）
```

### 2.2 历史好文的判定标准（第③项怎么算）

**排序主指标 = 收藏率**（收藏数 ÷ 点赞数）—— 小红书最重的分发信号

| 判定步骤 | 规则 |
|---|---|
| 1 | 拉自己全部笔记的互动数据（点赞/收藏/评论）|
| 2 | 算每篇的**收藏率**，按收藏率降序 |
| 3 | 取 **Top 30%** 作为「好文样本」|
| 4 | 从好文样本里提取特征：**题材、标题句式、封面类型、发布时间段、字数** |
| 5 | 这些特征 → 作为生成的"风格参考"（不是照抄）|

**补充指标**（收藏率相同时比较）：互动率（(赞+藏+评)/浏览）> 评论数

### 2.3 七天滑动窗口参数

| 参数 | 值 | 说明 |
|---|---|---|
| 窗口大小 | **7 天** | 一个完整叙事单元 |
| **每天发几条（N）** | 用户可选 **1–9**（默认 2）| 存 `settings.posts_per_day` |
| **初始产出总量** | **7 × N 篇** | 如 N=2 → 14 篇 |
| **每日生成次数** | **1 次** | 生成"第 7 天"那批（N 篇），补到队尾 |
| 窗口推进 | 每天前移 1 天 | 已发内容出窗 |
| 补货阈值 | 余量 < 7 天 | 自动触发补充（正常情况每天补 1 天即可）|

**七天叙事结构**（每天的角色）：
| 天 | 角色 | 作用 |
|---|---|---|
| D1 | 痛点共鸣 | "说的就是我" |
| D2 | 工具/认知 | 低成本第一步 |
| D3 | 方法展示 | 秀专业度（收藏最高）|
| D4 | 场景延伸 | 穿搭/场合延展 |
| D5 | 案例证明 | 信任峰值 |
| D6 | 价值升维 | 讲清底层逻辑 |
| D7 | 行动转化 | 明确下一步 |

**硬约束**：每天必须承接前一天结论 + 留钩子给下一天。

### 2.4 生成前的数据波动判断（每天 1 次）

| 参数 | 值 |
|---|---|
| 对比基准 | 账号**近 30 天均值** |
| 判定为上偏 | 单篇互动 **> 均值 × 1.5** → 明天偏向该题材 |
| 判定为下偏 | 单篇互动 **< 均值 × 0.5** → 明天回避该题材 |
| 正常区间 | 0.5× ~ 1.5× → **照计划表走** |
| 调整幅度 | 支柱占比 **±10%** |
| 留痕 | **必须记录"为什么改"**（写入反馈记忆 L3）|

## 3. 数据反馈规格（数据如何影响内容）

### 3.1 采集时点与基准

| 参数 | 值 |
|---|---|
| 采集时点 | 发布后 **24 / 48 / 72 小时** 各采集一次 |
| 对比基准 | 账号**近 30 天同指标均值** |
| 数据来源 | 创作者中心（浏览/涨粉）+ MCP（赞/藏/评）|

### 3.2 加权规则（写回题材权重表）

```
表现 = 该篇互动量 ÷ 账号近30天均值

表现 > 1.3   →  该题材权重 +20%（标记「成功题材」）
0.7 ≤ 表现 ≤ 1.3  →  不变
表现 < 0.7   →  该题材权重 −30%（标记「回避题材」）
连续 3 周 < 0.7  →  标记「暂停」，提醒人工决策
```

**第一判据**：**收藏率**（收藏 ÷ 点赞），比点赞更能反映内容价值。

## 4. 对标账号规格

| 参数 | 值 |
|---|---|
| 数量 | **5–8 个** |
| 手动指定 | 客户填（最准）|
| **自动发现规则** | 搜索行业关键词 → 前 20 条笔记里**出现 ≥3 次**的作者 → 列为候选 |

**红线**：只看题材方向/句式/节奏，**禁止直接改写**；生成内容仍过 60% 查重。

## 5. 数据分析规格

### 5.1 指标清单与来源

| 指标 | 来源 | 状态 |
|---|---|---|
| 浏览量 | 创作者中心 `view_count` | ✅ |
| 涨粉 | 创作者中心 `rise_fans_count` | ✅ |
| 首页曝光 | 创作者中心 `home_view_count` | ✅ |
| 平均观看时长 | 创作者中心 `view_time_avg` | ✅ |
| 点赞/收藏/评论/分享 | MCP + 创作者中心（含每日趋势）| ✅ |
| 粉丝总数/关注/获赞收藏 | MCP `/user/me` | ✅ |
| **咨询数 / 到店数** | **手工填报** | ⬜ 待做 |

### 5.2 分析维度（6 类）

| # | 维度 | 具体算法 |
|---|---|---|
| 1 | 内容表现 | 各篇的赞/藏/评/**收藏率**，与账号均值比 |
| 2 | 账号成长 | 每日涨粉（`rise_fans_list`）+ 与发布量的相关 |
| 3 | 发布规律 | **发布时间 × 表现**（分 4 个时段统计均值）|
| 4 | 题材表现 | 各题材互动 vs 账号均值 |
| 5 | 竞品对比 | 对标账号的更新频率/爆款题材/互动倍数 |
| 6 | 趋势变化 | 近 7 天滑动平均 vs 近 30 天 |

### 5.3 建议生成规则（何时输出什么建议）

| 触发条件 | 输出建议 |
|---|---|
| 某题材收藏率 > 均值 ×1.3（连续 2 篇）| "加大该题材占比" |
| 某题材互动 < 均值 ×0.7（连续 3 篇）| "建议暂停该方向" |
| 某时段平均表现 > 其他时段 ×1.5 | "建议发布时间改到 X 点" |
| 浏览量降但收藏率持平 | "属曝光问题，建议加话题标签/蹭平台活动" |
| 涨粉 +0（连续 7 天）| "账号处于停滞期，建议复盘封面与标题" |

## 6. 查重规格（60% 门禁）✅ **已落地**

| 参数 | 值 |
|---|---|
| **门禁阈值** | **60%** |
| 比对对象 | 文案库**全部历史**（现 46 篇，持续增长）|
| 自动重写次数 | 最多 **3 次**，仍不过 → 转人工 |
| **比对维度权重** | 标题 **30%** + 正文结构 **25%** + 核心观点 **25%** + 表达方式 **20%** |
| 算法 | **两段式**：① 关键词/ngram 粗筛（快）→ ② 向量相似度精算（BGE-M3 本地免费）|
| 触发动作 | ≥60% → 自动退回重写，并记录哪一项超标 |
| **实现位置** | `server/src/dedupe.js`；接口 `POST /api/duplicate/check`、`/scan` |
| **边界规则** | 一方正文 <30 字（导入的历史笔记只有标题）→ **退回标题单维判定**，否则标题抄袭判不出来 |
| **实测校准** | 改几个字 94% / 改标题同结构 87.5% / 同行业不同题材 16% / 完全不同 11% / 历史标题 100% 拦截 |

## 7. 评论区回复规格

### 7.1 轮询与分流

| 参数 | 值 |
|---|---|
| **轮询频率** | **每 5 分钟** ✓ 用户指定 |
| **监控方式** | **纯规则（不用 AI）** —— 一次 HTTP 拉通知，零 AI 成本 |
| 数据来源 | MCP `/notifications/list`（实测能拿到评论原文 + 评论ID + 笔记ID）|

**分流规则（按顺序判断）**：
| # | 条件 | 动作 |
|---|---|---|
| 1 | 黑名单命中 | 只记录，不回复 |
| 2 | 已回复过（去重）| 跳过 |
| 3 | 纯表情/符号 | 跳过或简回 |
| 4 | **命中知识库** | → **AI 生成回复**（真数据路由）|
| 5 | 未命中知识库 | → 回兜底话术 + **提醒人工**（不猜测）|

### 7.2 人设卡（7 个字段）

| 字段 | 示例 |
|---|---|
| 身份 | 绮点化妆学校的课程顾问小绮 |
| 称呼 | 宝子 / 同学 |
| 语气 | 亲切、专业、不油腻、不说教 |
| 长度 | **30–60 字** |
| 口头禅 | 悄悄告诉你 / 这个真的有用 |
| **禁用词** | 绝对化用语（最好/第一/永久）、疗效承诺、私下转账引导 |
| 结尾动作 | 可引导私信（视客户意愿）|

### 7.3 复核与放量

| 阶段 | 策略 |
|---|---|
| 前 3 天 | **全部进"待确认"，人工点一次再发** |
| 3 天后 | 命中知识库的自动发；未命中的提醒人工 |
| 全程 | 所有回复入库：**可查、可改、可撤回** |

## 8. 发布规格 ✅ **已落地**

| 参数 | 值 |
|---|---|
| 状态机 | `pending → precheck → publishing → done / failed` |
| 调度 | 服务内置扫描，**每 60 秒**一次 |
| **预检时点** | 计划发布前 **15 分钟** |
| 预检项 | 登录态 / 查重通过 / 图片文件存在 / 网络可用 |
| 失败重试 | 最多 **3 次**，指数退避 |
| **发布间隔** | **≥30 分钟**（同账号，防风控）|
| 每日上限 | 可配置（建议 ≤3 条）|
| 重启恢复 | 从 `publish_tasks` 表恢复未完成任务 |

### 8.1 建议发布时间（三层依据）

```
第 1 层：自己账号历史（最准）—— 哪个时段发的表现最好
第 2 层：对标账号 —— 他们爆款的发布时间分布
第 3 层：行业经验值（冷启动兜底）——
        07:30–09:00 通勤向
        12:00–13:30 午休种草
        19:00–22:00 ⭐ 主力（美业类黄金时段）
        21:00–23:00 情感/故事向
```

**输出示例**："建议 19:30 —— 你近 30 天 19:00–21:00 发布的平均点赞是其他时段 1.8 倍；对标 @XX 70% 爆款也在此段。"

**冷启动**（自己没数据）：只用第 2、3 层，并标注"数据积累中，建议仅供参考"。

**实现位置**：`server/src/publish.js`（`bestPublishTime()` / `precheck()` / `runTask()` / `tick()`）；
接口 `GET /api/publish/best-time`、`GET /api/publish/tasks`、`POST /api/publish/schedule`、`/precheck`、`/tasks/:id/run`、`/tasks/:id/cancel`、`/publish/now`。
