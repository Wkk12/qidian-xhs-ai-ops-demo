## 1. 项目定位

| 项 | 内容 |
|---|---|
| 目标用户 | 化妆培训机构、美妆、穿搭、时尚行业的小红书运营人员 |
| 交付形态 | 部署在**客户本地电脑**（Windows 优先）的运营平台 |
| 使用者画像 | **不懂技术**（不会写提示词、不会配环境） |
| 硬性约束 | **不依赖 Hermes 或任何外部 Agent**，独立运行；**后台静默**，不需要前端启动插件 |
| 组成 | Wkk 仓库的 **Vue 前端页面** + 本地服务 + **小红书 MCP** + AI 接口（DeepSeek / qweapi） |

## 2. 六大功能模块

### M1 · 自动发布
- 通过小红书 MCP 自动发布**图文 / 视频**
- 支持**立即发布**与**定时发布**
- 发布状态机：防重复发布、失败重试、进程重启后可恢复
- 发布前预检（提前 15 分钟）：登录态、文案查重通过、图片文件存在、网络可用
- 合规红线：不绕过风控/验证码；高风险内容必须人工确认

### M2 · 内容自动生成 ⭐核心
**输入源（三类）**
1. 账号**历史已发内容**
2. **用户需求**（输入框直接说）
3. **运营策略**：行业运营方向、时下热门、账号运营数据

**滚动生成**
- 每次生成**未来一周（7 天）**内容 → 用户确认 → 支持实时调整
- 七天必须**同一条内容主线**，后一天承接前一天，不得随机拼凑
- 每日复盘后**滚动优化后续 6 天**

**交互能力（用户明确要求，缺一不可）**
- ① **策略沟通输入框**：用户可随时跟 AI 沟通方向、策略
- ② **每条内容旁配输入框**：随时沟通"这里要改"
- ③ **编辑功能**：用户可直接修改文案

**查重门禁**
- 新内容与历史文案库**逐篇比对**，相似度达到 **60% 自动退回重写**（最多 3 次；仍不通过交人工）

### M3 · 配图
**两种来源**
1. 用户**自己上传**图片
2. **AI 生图**（走 qweapi 的 **image2.5**）

**两个档位**
- **档位 1**：直接根据内容生图
- **档位 2**：根据用户要求生图 → **先经 DeepSeek 丰富提示词**再生图
  - ⚠️ **不能直接使用用户写的提示词**（客户不会写提示词）

**其他**：图片可替换、重新生成、删除；支持手动编辑

### M4 · 数据分析
- 监控**每日数据**：浏览、涨粉、咨询、到店
- **实时分析** + 每日复盘报告
- **监控同行（对标账号）数据**
- 输出**调整策略** → **联动 M2**（优化后续内容方向）

**数据维度建议（用户要求先提，待其补充完善）**

| 维度 | 建议指标 |
|---|---|
| 内容表现 | 曝光量、阅读量、互动率、收藏、评论、分享、完播 |
| 账号成长 | 粉丝净增、粉赞比、取关数、涨粉来源 |
| 转化漏斗 | 私信数、咨询数、加微数、到店数 |
| 内容特征 | 发布时间、标题类型、封面类型、话题标签、正文长度 |
| 竞品监控 | 同行爆文、发布频率、话题选择、互动量级 |
| 行业趋势 | 热搜词、平台活动、季节性话题 |

### M5 · 数据库同步（Obsidian）
**两个数据区（用途不同，不可混）**
- **部分 1 · 内容备份**：每天发送的内容存档 → 供后续**调整策略**参考
- **部分 2 · 业务知识库**：用于**自动回复客户**的知识储备

**载体**：Obsidian（本地 markdown 库）

### M6 · 自动回复客户 ⭐（评论 + 私信 双通道）
**回复范围（两者都要）**
1. **评论区自动回复** —— 有人评论笔记 → AI 根据知识库回复
2. **私信自动回复** —— 有人私信咨询 → AI 根据知识库回复

**硬性要求**
- **必须使用知识库**内容回复（不得凭空编造）
- **兜底机制**：
  - 不会答 / 遇到超出知识库的问题 → 回复客户"**现在联系经理，请稍等**"
  - **人工介入后，对该客户的自动回复暂停**（不再自动回）
- 实现方式：本地模型或大模型监控 + 回复
- **必须静默运行**：不需要在前端启动任何插件，全部后台进行
- 回复需过合规检查（不乱承诺、不出现医疗违规表述）

**技术通道现状**
| 通道 | MCP 支持 | 候选方案（GitHub 调研见附录） |
|---|:---:|---|
| 评论回复 | ✅ 支持 | MCP 原生 `/feeds/comment/reply`、`/notifications/reply` |
| 私信回复 | ❌ **不支持** | 见附录 A（第三方项目 / RPA / 客服工具） |

## 3. 技术约束（硬性）

1. **不依赖其他 Agent** —— 客户电脑没有 Hermes，也不给客户装 Agent
2. **静默运行** —— 后台服务，前端不启动插件
3. **环境补齐** —— 交付时必须解决运行环境（一键安装 / 依赖检测 / 自动补齐）
4. **密钥安全** —— 密钥只存客户本机，前端/日志/仓库**不得出现明文**
5. **平台合规** —— 不绕过登录、风控、验证码
6. **组件复用** —— 前端用 Wkk 仓库那份 Vue 页面；发布用小红书 MCP

## 5. 待确认问题（需你拍板）

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | **后端技术栈**：她方案是 Java+Spring Boot（客户要装 JDK，小白不友好） | 换 **Node.js**（与前端同栈）或 **Python FastAPI** |
| 2 | **M6 私信回复怎么做**（MCP 无私信能力） | 三选一：只做评论区 / 接第三方客服工具 / RPA 浏览器自动化 |
| 3 | **M4 是否用 n8n**（客户电脑要装 n8n + 额外运维） | 建议不用，服务内置调度更轻 |
| 4 | 单账号还是多账号？ | 首版单账号 |
| 5 | 客户电脑是 Windows 还是 macOS？ | 影响打包方案 |
| 6 | 配图是否需要人物一致性 / 机构 Logo / 模特授权管理？ | — |
| 7 | 无人值守模式的边界（哪些必须人工确认）？ | 高风险内容一律人工 |
| 8 | 到店数等平台拿不到的指标 → 人工录入？ | 建议手工填报 |

### A.4 结论与建议
1. **评论回复**：MCP 原生已支持，**无需外部项目**；若要更强的"自动发现评论并回复"，可参考 `Redbook-Search-Comment-MCP2.0`（同为 MCP 思路，可融合）。
2. **私信回复**：MCP 无能力 → **首选 `XHS-YYDS`（私信通自动回复）或 `xhs-dispatch-relay`（统一收件箱）** 作参考实现；注意这类项目多依赖**浏览器自动化/RPA**，需评估稳定性与风控风险。
3. **数据分析**：`xhs_douyin_content` 抓创作者中心数据的思路**可直接借鉴**（比 MCP 能拿到的指标更全，尤其"粉丝增量/完播"）。
4. ⚠️ **风险提示**：A.2 里多数第三方项目带"引流获客/矩阵营销"性质，**自动化私信属平台高风险行为**，正式产品里需做频率控制 + 人工确认，避免客户账号被限。
