## 0. 技术栈方案（需先拍板）

| 层 | 推荐方案 | 理由 | 备选 |
|---|---|---|---|
| 前端 | **Vue 3 + Element Plus**（沿用 Wkk Demo） | 已有 1188 行可复用 | — |
| 本地服务 | **Node.js (Fastify/Express)** 或 **Python FastAPI** | **免装 JDK**；打包成一键安装更简单 | Java Spring Boot（她原方案，客户需装 JDK，不推荐） |
| 数据库 | **SQLite** | 零安装、单文件、好备份 | MySQL（多账号再评估） |
| 发布通道 | **小红书 MCP**（Go 二进制，本地 18060） | 已下载可用；也能单独编译进交付包 | — |
| 文案 AI | **DeepSeek API** | 已确认可用 | — |
| 配图 AI | **qweapi image2.5**（需先开通渠道） | 用户指定 | apikiki nano banana pro（已验证 4K 可用） |
| 定时调度 | **服务内置**（node-cron / APScheduler）+ 持久化任务表 | 免装 n8n，重启可恢复 | n8n（重，需额外运维） |
| 打包交付 | **Electron 外壳** 或 **pkg/单文件 + 安装脚本** | 一键装、桌面快捷方式、开机自启 | — |

> ⚠️ **核心分歧点**：她写了 Java + Spring Boot。给"不懂技术的客户"交付时，**JDK + Maven + 数据库** 是三道坎。建议换成 **Node 单栈**（前端同语言，打包成 exe 最省事）。

## 2. 阶段明细（任务拆分）

### P0 · 需求确认 + 接口契约（1–2 天）
**目标**：把所有"能不能做"变成有返回值、有异常处理的确定契约。

- [ ] 实测 MCP 全部端点：登录、发布（图文/视频）、搜索、详情、通知列表、评论回复、点赞
- [ ] 确认 MCP **私信能力缺口** → 定 M6 方案（评论区 / 第三方客服 / RPA）
- [ ] 核对 DeepSeek 请求格式、模型名、限额、错误码、重试规则
- [ ] 开通并实测 qweapi **image2.5**（现为 404）；测 apikiki nano banana pro 作为备选
- [ ] 确认单/多账号、Windows/macOS、部署范围
- [ ] 输出：接口文档 + 系统架构图 + 数据流图 + 安全边界

**交付物**：`docs/api/`、`docs/architecture/`
**验收**：每个外部能力都有**可运行的最小调用验证**和失败提示

### P1 · 工程骨架 + 本地存储 + 环境检测（2–3 天）
**目标**：客户电脑能启动前后端、完成健康检查、保存本地数据。

- [ ] 前端（沿用 Demo）接入本地服务（替换 mock 数据）
- [ ] SQLite 建表：账号 / 内容 / 素材 / 计划 / 发布任务 / 指标快照 / 日志 / 任务锁
- [ ] 环境检测：操作系统、端口、磁盘、网络、运行时、MCP 文件存在性
- [ ] 一键启动脚本 + 健康检查页
- [ ] 脱敏日志 + 本地备份目录

**验收**：全新测试机按引导启动，健康检查全绿

### P2 · 账号授权 + 密钥安全（2 天）
- [ ] 小红书扫码登录（走 MCP 的 qrcode 端点），登录态持久化
- [ ] DeepSeek / qweapi 密钥：本机加密保存，前端只显示**掩码**
- [ ] 三步式首次连接向导
- [ ] 状态区分：未配置 / 检测中 / 可用 / 过期 / 限额不足 / 连接失败（大白话提示）

**验收**：断网、错 Key、过期授权、服务未启动 四种情况都有明确提示

### P3 · 账号定位 + 文案库 + 查重门禁（3–4 天）
- [ ] 同步账号历史内容 → 提取人设、受众、内容支柱、语气、卖点、转化目标
- [ ] 建立统一文案库（历史 + 生成）
- [ ] 查重算法：比较标题、结构、核心观点、表达方式 → 给出最高相似文章 + 重复位置
- [ ] **60% 硬门禁**：达阈值自动重写（最多 3 次）→ 仍不通过转人工

**验收**：重复样本必被拦截；通过样本能追溯比较对象与分数

### P4 · 七天连续大纲引擎（3 天）
- [ ] 根据账号定位 + 目标 + 内容支柱生成**周主题**
- [ ] 七天节点分工：痛点 → 认知 → 方法 → 延伸 → 证明 → 价值 → 转化
- [ ] 每个节点保存"承接什么 / 提供什么 / 为下一天留什么"
- [ ] 支持编辑后**重新检查连贯性**（不整周无条件重生成）
- [ ] 版本记录 + 回滚

**验收**：随机抽查任意连续三天，主题/观点/行动引导能自然衔接

### P5 · 内容工坊 + 配图 + 编辑（4–5 天）⭐工作量最大
- [ ] 生成参数：天数、每天条数、图片数量、图片类型、主题、风格
- [ ] DeepSeek 生成：标题、正文、标签、封面字、图片提示词
- [ ] **配图两档**：
  - 档位 1：直接用内容生图
  - 档位 2：**DeepSeek 丰富提示词** → 再生图（用户提示词不直接使用）
- [ ] ⭐ **三个交互入口**（用户明确要求）：
  - 策略级输入框（沟通方向/策略）
  - 每条内容旁输入框（沟通具体修改）
  - 直接编辑功能（改文案/换图/调顺序/改标签）
- [ ] 每次生成先过查重，再进可编辑草稿
- [ ] 版本恢复

**验收**：生成七天内容后，任意一篇可编辑、替图、重生成；未过查重的内容不能进排期

### P6 · 发布队列 + 定时 + MCP 发布（3–4 天）
- [ ] 可持久化发布状态机（避免重复发布）
- [ ] 定时调度：进程重启后自动补载未执行任务
- [ ] 发布前 15 分钟预检：授权 / 门禁 / 图片文件 / 网络
- [ ] 调用 MCP 发布 → 回写结果 + 平台内容 ID
- [ ] 失败重试策略 + 失败原因展示

**验收**：定时任务准时发布；断电重启后任务不丢不重

### P7 · 数据分析 + 同行监控 + 复盘联动（3–4 天）
- [ ] 每日数据采集（MCP 可得指标 + 人工录入兜底）
- [ ] 数据看板（内容表现 / 账号成长 / 转化漏斗 / 内容特征）
- [ ] **同行监控**：对标账号爆文、频率、话题
- [ ] 每日复盘报告 → **策略建议** → 联动 P4/P5 **优化后续 6 天**

**验收**：复盘结论能落到具体的内容调整建议上，并能在内容工坊一键应用

### P8 · 自动回复 + Obsidian 知识库（4–5 天，技术待定）
**覆盖两条通道**：① 评论区回复 ② 私信回复

**评论回复（已有能力，可直接做）**
- [ ] 定时拉取 MCP 通知（`/notifications/list`）→ 发现新评论
- [ ] 知识库检索 → 生成回复 → MCP 回复（`/feeds/comment/reply`、`/notifications/reply`）
- [ ] 回复记录落库，便于人工复核

**私信回复（MCP 不支持，需选方案）**
- 候选 A：集成 `puyujian/XHS-YYDS`（私信通自动回复）思路
- 候选 B：集成 `Liangqingkui8/xhs-dispatch-relay`（统一收件箱 + 关键词自动回复）
- 候选 C：自研浏览器自动化（Playwright 复用登录态）
- 候选 D：接第三方客服工具（ChatGPT-On-CS 类）
- [ ] **评估后再选型**（需权衡：稳定性 / 风控风险 / 静默运行可行性）

**通用能力**
- [ ] Obsidian 双数据区：**内容备份区**（每日发出内容）+ **业务知识库**（回复用）
- [ ] 知识库检索（向量/关键词）+ AI 回复生成
- [ ] **兜底机制**：不会答 → 回"现在联系经理，请稍等"
- [ ] **人工介入开关**：某客户人工接管后，对该客户的自动回复**自动暂停**
- [ ] **静默运行**：后台服务 + 系统托盘，无需前端插件
- [ ] 回复合规检查（避免乱承诺、避免医疗违规表述）

**验收**：知识库内问题自动准确回复；库外问题正确兜底；人工介入后确实停止

### P9 · 一键安装 + 环境补齐 + 交付（3 天）
- [ ] 运行时依赖检测与**自动补齐**（客户电脑没有 Node/Python/MCP 时）
- [ ] 一键安装包 + 桌面快捷方式 + 开机自启
- [ ] 故障诊断工具（一键体检 + 导出日志）
- [ ] 卸载入口
- [ ] 客户机实机验收 + 操作手册（图文）

**验收**：全新电脑按手册 15 分钟内装好并成功发布一条内容

## 3. 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| **MCP 无私信能力** | M6 自动回复私信做不了 | ① 只做评论区回复 ② 接第三方客服（ChatGPT-On-CS 类）③ RPA 浏览器自动化（需常开浏览器） |
| **image2.5 无渠道**（现 404） | M3 配图不可用 | 开通渠道 / 备案 nano banana pro |
| **客户电脑无 Hermes** | 不能复用现有能力 | 独立服务架构 + MCP 自包含 |
| **小白环境** | 装不上、跑不起来 | 一键安装包 + 自动依赖补齐 + 故障诊断 |
| **平台风控** | 账号被限/封 | 人工确认 + 频率控制 + 不碰违规内容 |
| **Java 栈门槛** | 交付成本高 | 建议换 Node 单栈 |
