## ADR-001 技术栈选 Node 单栈

- **日期**：2026-09（项目启动）
- **背景**：客户机不装 agent，需纯本地自包含运行；技术栈越简单越好。
- **选项**：
  - A. Node 单栈 —— 前后端同语言，客户机只需 Node
  - B. Python 后端 + Node 前端 —— 需两套运行时
  - C. 前后端分服务（dev server + API）—— 客户机遇掉线
- **决定**：选 **A**
- **理由**：单一运行时、启动脚本简单、交付面最小
- **代价**：失去 Python 生态（如后续要跑 ML，需另起进程）

## ADR-002 数据库用 Node 22 内置 `node:sqlite`

- **背景**：需要本地数据库，但不想让客户装任何东西。
- **选项**：
  - A. `node:sqlite`（Node 22 内置）—— 零依赖
  - B. `better-sqlite3` —— 需编译原生模块（客户机无编译环境则失败）
  - C. PostgreSQL —— 需安装服务
- **决定**：选 **A**
- **理由**：零依赖是交付硬要求；Node 22 已内置，客户机装上即用
- **代价**：API 比 better-sqlite3 略简；无 WAL 调优空间（当前数据量下无影响）

## ADR-003 前端定稿用 Wkk 的 GitHub 页面，只换数据源

- **背景**：页面视觉已由 Wkk 定稿，用户要求不得改设计。
- **决定**：**只改数据来源（假数据→真数据），HTML 结构与 CSS 类名一个不改**
- **理由**：尊重已定稿的设计；避免"改着改着变成另一个产品"
- **代价**：新增交互控件受限（如编辑弹窗需用行内样式，不能引入新 CSS 类）→ 已写入宪法红线 2

## ADR-004 单服务托管（后端直出前端）

- **背景**：曾出现"前端 dev server 掉线 → 用户打不开页面"的事故。
- **选项**：
  - A. 保持双服务（Vite dev + API）
  - B. 后端 `fastifyStatic` 直出 `web/dist` + 旧端口转发兼容
- **决定**：选 **B**
- **理由**：交付面最小，客户不会遇到"开发服务器没起"的问题
- **代价**：前端改动后**必须构建**才能生效（已写入技能"已知坑"）

## ADR-005 查重：正文缺失时退回标题单维判定

- **日期**：2026-09-18
- **背景**：导入的历史笔记**只有标题、没有正文**，四维加权上限被压到 30%，导致"标题完全一样"也判不出来（实测仅 30%，不拦截）。
- **选项**：
  - A. 给历史笔记补正文 —— 成本高，且补的是编造内容
  - B. 正文 <30 字时退回标题单维判定 —— 能比什么就比什么
- **决定**：选 **B**
- **理由**：标题完全相同就该拦截，不该被"其他维度没数据"稀释
- **代价**：标题单维判定误报率略高（仅标题像但内容不同会被拦）→ 用 `excludeId` 缓解

## ADR-006 数据指标分两层取数

- **背景**：用户要求浏览量/涨粉明细必须实现；但 MCP **没有**这些字段。
- **选项**：
  - A. 只靠 MCP —— 拿不到浏览量/涨粉
  - B. MCP + 创作者中心 API 双通道
- **决定**：选 **B**
  - 点赞/收藏/评论/评论原文 → **MCP**
  - 浏览量/涨粉/曝光/观看时长 → **创作者中心 galaxy API**（复用 `.xiaohongshu.com` 泛域 cookie，无需额外签名）
  - 咨询数/到店数 → 平台无此数据，**手工填报**
- **理由**：实测创作者中心可直调且免签名
- **代价**：多一个取数通道要维护登录态

## ADR-007 抠图只用 BiRefNet

- **背景**：多种抠图模型可用，效果差异大。
- **决定**：**只用 `birefnet-portrait`（BiRefNet）**，禁用 u2net/isnet 等
- **理由**：实测发丝/半透明边缘质量最好，且用户明确要求
- **代价**：模型较重、速度略慢

## ADR-008 生图不做小号中文，文字一律 Pillow 排

- **背景**：nano banana pro 渲染小号中文**必错**。实测两次：
  - `无人足球训练舱` → "无人巫球种棚舱"
  - `公园艺术季` → "公园艺术生活节" / 糊成一团
- **决定**：重要中文一律用 Pillow 排版后合成，**不让生图模型写小号中文**
- **理由**：设计师对文字零容忍；排版精度可控且不花 API
- **代价**：增加后处理步骤

## ADR-009 图片交付走文件通道

- **背景**：微信"图片"通道必压缩（4K → ~1–2MB 缩略图），用户会判定"这不是 4K"。
- **决定**：4K/大图交付**打包 zip 走"文件"通道**；预览图单独发并注明"这是压缩预览"
- **理由**：文件通道不压缩
- **代价**：用户需多一步解压

## ADR-010 建立 SDD 标准并重审项目

- **日期**：2026-09-18
- **背景**：项目有 11 份文档但不符合 SDD；审计发现 **16 个接口代码有文档无**，全部是 AI 擅自新增。
- **决定**：建立 `sdd-standard` 技能（六铁律 + 七文件 + 校验器），并把本项目迁移到该标准
- **理由**：没有"宪法"约束时，AI 必然自由发挥；验收标准不写则"做完没做完"靠吵
- **代价**：每个任务多一道"写验收标准"的成本（小改动可豁免，见技能 §6）

## ADR-011 交付前删除所有密钥

- **日期**：2026-09-18
- **背景**：用户明确要求"交付的时候记得删除 sk-REPLACED-BY-CUSTOMER-KEY"
- **决定**：交付前删除 `server/.env` 中的 DeepSeek Key；清空 cookies；清空测试数据
- **理由**：用户密钥不外泄；客户需自备 Key
- **代价**：交付包开箱不可直接用，需客户填 Key（已在 R16 加引导）
