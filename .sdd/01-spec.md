### R1 历史内容导入

**描述**：把账号已有笔记导入本地文案库，作为查重的比对底库。

**验收标准**：
- [ ] 调用导入 → 从平台拉取全部笔记，跳过无标题/重复项
- [ ] 导入结果：实际入库条数与拉取数之差 = 跳过数（可对账）
- [ ] 重复导入同一批 → 不产生重复行（幂等）
- [ ] 无登录态时 → 返回明确错误，不静默失败
- [ ] 异常：平台返回空列表 → 返回 `{ok:true, imported:0}` 而不报错

**实测基线**：拉 60 篇 → 入库 46 篇（跳过 14 篇无标题/重复）

### R2 AI 内容生成（7 天窗口）

**描述**：按运营计划表 + 用户输入，生成 7 天内容；用户可指定每天条数；之后每天补 1 天（第 7 天）。

**验收标准**：
- [ ] 输入"每天 N 条 + 天数 D" → 生成 D×N 条，条目数可对账
- [ ] 四参考系加权生效：用户输入 0.45 / 计划表 0.25 / 历史好文 0.20 / 热榜 0.10
- [ ] 用户输入的方向被遵循：给定"语气亲切像学姐"→ 生成正文出现该人设口吻
- [ ] 七天叙事结构：D1 痛点 → D7 转化，且**每天承接前一天结论**（D2 正文提及 D1 的观点）
- [ ] 每条含：标题 / 正文 / 话题标签 / 所属支柱 / 生成理由
- [ ] 输出为严格 JSON，解析成功率 100%（解析失败自动修复重试）
- [ ] **性能**：单批 2 天内容 ≤10 秒
- [ ] 异常：未给 API Key → 返回明确错误提示，不抛裸异常

**实测基线**：2 天内容 4.4–4.6 秒完成；生成标题"手残党化妆是不是总像糊墙？"，D2 开头"昨天说新手要做减法"（承接成立）

### R3 查重门禁

**描述**：内容与历史库比对，超阈值拒绝并自动重写。

**验收标准**：
- [ ] 阈值 60%，四维权重：标题 30% / 结构 25% / 观点 25% / 表达 20%
- [ ] 几乎同一篇（改几个字）→ 相似度 ≥90%，`pass=false`
- [ ] 同题材改标题 → 相似度 ≥80%，`pass=false`
- [ ] 完全不同题材 → 相似度 ≤20%，`pass=true`
- [ ] **历史笔记无正文时退回标题单维判定**：标题完全相同 → 100% 拦截
- [ ] 生成流程自动重写：超标 → 重写最多 3 次；仍超标则落库但标记 `dupPass=false`
- [ ] **性能**：比对 500 篇库 ≤300ms
- [ ] 异常：空标题+空正文 → 不报错，`score=0`

**实测基线**：①94.1% ②87.5% ③11.3% ④16.4%，历史标题 100% 拦截，比对 46 篇

### R4 文案编辑与审核流转

**描述**：草稿可在页面直接编辑，并可标记通过/退回。

**验收标准**：
- [ ] 点"编辑内容" → 弹窗载入原标题/正文/标签（值非空）
- [ ] 改标题后保存 → 重新读取接口，标题已变（**持久化成功**）
- [ ] 状态流转：`draft → approved / rejected`，页面状态同步更新
- [ ] "立即查重" → 显示四维得分 + 最像的那篇标题 + 是否通过
- [ ] 查重结果落库（`dup_score`/`dup_with` 可回读）
- [ ] 异常：保存时标题为空 → 允许，但不写入空字符串覆盖原值

### R5 定时发布 + 建议发布时间

**描述**：内容可排期到指定时间自动发布；系统给出建议发布时间。

**验收标准**：
- [ ] 排期到未来时间 → 任务状态 `pending`，**且不立即发布**
- [ ] 建议时间接口返回 `recommended`（HH:mm）+ 至少 1 条 `reasons`
- [ ] 三层依据：自己历史数据（有则用）> 对标 > 行业经验；无自己数据时标注"数据积累中"
- [ ] 行业兜底时段至少含 4 档（含晚间黄金档 19:30）
- [ ] 同一条内容重复排期 → 返回已有任务，不产生第二条
- [ ] 取消任务 → 状态 `canceled`，且内容状态回到 `approved`

**实测基线**：建议 19:30（industry-only）+ 理由；排期到 09-18 19:30 后状态 pending ✅

### R6 发布状态机与预检

**描述**：可恢复的发布状态机，发布前五项预检，失败重试。

**验收标准**：
- [ ] 状态机：`pending → precheck → publishing → done / failed / canceled`
- [ ] **调度器不误发**：排到明天的任务，跑一次调度后仍为 `pending`
- [ ] 到点前 15 分钟执行预检；预检不过 → 状态 `failed` 且 `error` 写明原因
- [ ] 预检 5 项：登录态 / 查重 / 配图 / 正文长度 / 发布间隔
- [ ] 距上次发布 <30 分钟 → 预检拦截，**不发送**（防风控）
- [ ] 失败重试最多 3 次，之后置 `failed`
- [ ] 重启服务后未完成任务仍可被调度（状态全部落库）
- [ ] 异常：内容被删除 → 任务置 `failed`，错误写明"内容已被删除"

**实测基线**：①登录态✓ ②查重23%✓ ③配图✗（正确拦截）④正文225字✓ ⑤首次发布✓

### R7 平台数据接入

**描述**：接入平台官方数据（浏览量/涨粉/曝光/观看时长）并绘制趋势。

**验收标准**：
- [ ] 返回近 7 天与近 30 天两个窗口
- [ ] 含指标：浏览量 / 涨粉数 / 首页曝光 / 平均观看时长 / 点赞 / 收藏 / 评论 / 分享
- [ ] 每个指标含**每日趋势数组** + **环比百分比**
- [ ] 页面 KPI 显示平台真实值（非本地快照），并标注来源
- [ ] 趋势曲线按每日浏览量绘制，X 轴为真实日期
- [ ] **性能**：首次加载 ≤12 秒（含平台请求）
- [ ] 异常：登录态失效 → 返回明确提示，页面显示"数据不足"而非 0 值误导

**实测基线**：近30天 浏览量 119(+296%) / 涨粉 1 / 曝光 28(+460%) / 观看 852 秒；趋势 08-16→09-15 共 30 天

### R8 行业热榜抓取

**描述**：按关键词抓取行业内爆款笔记，落库供生成参考。

**验收标准**：
- [ ] 手动触发 → 抓取并入库，返回每个关键词的 `fetched` / `saved`
- [ ] **定时抓取**：每天 09:30 与 20:30 各一次
- [ ] 关键词可配置（默认：化妆教程/新手化妆/底妆/眼妆/通勤妆）
- [ ] 榜单按热度排序：`点赞×1.0 + 收藏×1.5 + 评论×2.0`
- [ ] 重复抓取同一篇 → 不产生重复行（幂等，按 note_id）
- [ ] 封面图可正常显示（防盗链走本地代理）
- [ ] **抓取间隔 ≥3.5 秒**（实测更快会触发平台限流）
- [ ] 异常：平台限流 → 该关键词记 error，其他继续，不整体失败

**实测基线**：抓"底妆" → 20 条全部入库；榜单 21 条；封面 8/8 张加载成功

### R9 运营计划表

**描述**：账号定位 + 内容支柱占比 + 每天条数，作为无人工干预时的生成依据。

**验收标准**：
- [ ] 五个定位字段可读写：人设 / 目标人群 / 语气 / 核心卖点 / 转化目标
- [ ] 内容支柱支持 4–6 条，每条含名称 + 占比 + 说明，占比可改并落库
- [ ] "每天发几条"可读写（1–9）
- [ ] 保存后回读值与写入值一致（**持久化验证**）
- [ ] 页面显示换算关系：`每天 N 条 × 7 天 = 7N 篇`
- [ ] 异常：占比总和 ≠100% → 提示但不阻止保存

**实测基线**：写 2 条 → 回读 2 条 ✅；显示"7 天窗口共需产出 14 篇"

### R10 素材库

**描述**：上传图与 AI 生成图的统一存放位（"在线素材"），可删除、可挂到内容上。

**验收标准**：
- [ ] 上传图片 → 保存到本地并返回可访问 URL
- [ ] 列表显示真图（非占位图），支持按来源筛选（上传/AI生成/历史）
- [ ] 删除 → 从列表与磁盘同时移除
- [ ] 挂载：把素材关联到某条内容（发布时作为配图）
- [ ] 页面**只有一套网格**（不得出现演示假数据与真数据并存）
- [ ] 异常：上传非图片文件 → 拒绝并返回明确错误

### R11 对标账号监控

**描述**：自动发现同领域对标账号并监控其爆款。

**验收标准**：
- [ ] 自动发现：按 `author_id` 聚合热榜作者，出现次数 ≥ 阈值者进入候选
- [ ] **阈值行为**：默认 3；若候选 <5 个则自动逐级放宽（最低 2），并在返回中给出
      `thresholdAsked` / `thresholdUsed` / `relaxed`，页面须显示实际使用的阈值
- [ ] 数量控制在 5–8 个
- [ ] 监控 6 维度：更新频率 / 爆款率 / 题材分布 / 发布时段 / 互动结构 / 标题句式
      常态可用 4 维（②③⑤⑥）；**①④ 依赖发布时间，属"尽力而为"**：
      平台搜索结果不含时间，只能逐条拉详情（慢且限流）→ 取不到时须显示
      「数据不足，点深度分析补」而不是 0 或空值
- [ ] 爆款定义：点赞 ≥ 全站 80 分位（页面显示该阈值数值）
- [ ] 页面可增删对标账号；无样本的账号标注「失效（改名/注销）」而不阻塞其他账号
- [ ] **深度分析**（可选动作）：为补齐①更新频率与④发布时段，可按需拉笔记详情取发布时间
- [ ] 数据不足时**必须显式标注**「数据不足」，不得用 0 或空值冒充

**实现约束（实测得出，勿违背）**：
- MCP **搜索结果不含发布时间**（只有 type/displayTitle/user/interactInfo/cover）；
  发布时间只在**笔记详情**的 `note.time`（毫秒时间戳）。
- 拉详情需 **`xsec_token`**（搜索结果自带），故 `trends` 表必须存该字段。
- 1 条详情 ≈13 秒且平台限流 → 深度分析必须限制条数（≤6）并加间隔（≥4.5 秒）。

**实测基线**：热榜 136 条 / 5 关键词 → 达标作者 12 个 → 返回 8 个候选（阈值自动 3→2）；
6 维度中 4 项可算，①④待深度分析补时间

### R12 复盘报告与建议引擎

**描述**：定期产出数据复盘与可执行建议。

**验收标准**：
- [ ] 采集时点：发布后 24 / 48 / 72 小时
- [ ] 对比基准：账号近 30 天均值
- [ ] 阈值触发：>1.3× 均值记"优于"并建议加权；<0.7× 记"低于"并建议回避
- [ ] 首判据为收藏率（收藏/点赞）；**账号收藏全为 0 时退回「平均点赞」并在报告中显式告警**
      （实测本账号 60 篇收藏数全为 0，属真实数据非 bug）
- [ ] 建议必须可执行：含"改什么 + 改成什么 + 依据数据"
- [ ] 输出含：本期表现 / 与上期对比 / 3 条建议 / 下期支柱调整（±10%）
- [ ] 支柱未配置时用默认支柱兜底，并标注来源（`pillarSource`），保证该段永不缺失
- [ ] 异常：数据不足（<3 篇样本）→ 标注"数据积累中"，不强行给建议
- [ ] AI 总结失败时**结构化报告仍须可用**（降级不整体失败）

### R14 评论自动回复

**描述**：后台静默轮询评论，命中知识库则用 AI 以人设口吻自动回复。

**验收标准**：
- [ ] 轮询间隔 5 分钟，**纯规则机制监控**（不让 AI 做监控）
- [ ] 命中知识库 → AI 生成回复并发送；未命中 → **不回复**，进人工待办
- [ ] 回复人设来自"人设卡"配置，长度 30–60 字
- [ ] 禁用词表过滤（价格承诺/医疗宣称/竞品贬损等），命中则转人工
- [ ] 人工介入后 **对该用户暂停自动回复**
- [ ] 前 3 天全部回复需人工复核后才发送（观察期）
- [ ] 后台运行，**不装浏览器插件、不在前端手动启停**
- [ ] 异常：回复接口失败 → 记录失败并重试，不重复发送同一评论

- [ ] 出图含小号中文 → 必须 vision 核对，错误则重跑
- [ ] 异常：渠道不可用（404/无渠道）→ 明确报错，不静默降级

### R17 前端按钮真实性（架构约束）

**描述**：界面上不允许存在"点了只弹提示、不做事"的按钮 —— 按钮要么执行真实操作，要么给出明确的"未开放"提示。

**验收标准**：
- [ ] 「重新生成 7 天草稿」必须真调用 `POST /api/generate` 并渲染真实结果
- [ ] 「把素材加入 D3」必须真写 `assets.content_id`；无目标草稿时给出可执行提示（先去哪生成）
- [ ] 「重新检测环境」必须真重跑检测，不得回固定文案
- [ ] 模板引用的变量必须真实存在（不得引用已重命名/删除的变量，否则静默空白）
- [ ] 交付前须逐模块走查，确认每个按钮都有真实落点

## 明确不做（Out of Scope）🔴

> 不写这一节，AI 一定会自己加戏（历史上已发生：擅自加了 16 个接口）。

- **不做私信自动回复** —— 平台无接口（MCP 无 DM 端点），用户已明确暂缓
- **不做多账号管理** —— 一期只服务单账号
- **不做 Obsidian 同步** —— 用户明确"最后再解决"
- **不做移动端适配** —— 只做桌面浏览器
- **不做云端部署 / 多用户 / 权限体系** —— 本地单机运行
- **不做小红书以外平台**（抖音/视频号等）
- **不做评论区的"AI 监控"** —— 监控由规则完成，AI 只负责生成回复
- **不做数据大屏 / BI 报表** —— 数据只在运营模块内呈现
- **不做自动涨粉 / 刷量 / 互赞**等违规操作
- **不做成人向 / 露骨内容生成** —— 红线
