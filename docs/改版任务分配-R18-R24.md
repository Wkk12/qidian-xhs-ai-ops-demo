## 一、角色与文件所有权（🔴 违反 = 返工）

| 角色 | 唯一可写范围 | 明令禁止 |
|---|---|---|
| 执行者1 | `server/**`（src、package.json） | 碰任何 `web/**`（.vue/.css/.js） |
| 工作者 | `web/**`（src、styles、drafts） | 碰任何 `server/**` |
| 审核者 | 只读一切；产出写 `docs/审核-*.md` | 改代码 / 提交代码 |
| 管理者 | `.sdd/**`、`docs/**`、`.gitignore` | — |

- 🔴 `web/src/components/ModuleViews.vue` 同一时间**只允许一个写入者（当前 = 工作者）**。
- 🔴 提交纪律：只 `git add <自己范围内的文件>`；**禁止 `git add -A` / `git add .`**；消息格式 `feat(R18): …`。
- 🔴 服务纪律：主服务 = `127.0.0.1:8787`。改 `server/**` 后**必须重启**才生效（附录 A 端口杀法）；改 `web/**` 后**必须 `npm run build`**（产物 `web/dist` 由后端托管）；页面验证加 `?v=N` 硬刷。
- 🔴 证据纪律：完成 = 有**真跑证据**（curl 输出 / 页面 DOM 读数 / 测试数据结果）。不接受"应该好了"。**不许假数据、假开关、假动画**；数据拿不到就标注缺失（前端显示"平台不提供 / 数据积累中"），**不许编**。

## 二、接口契约 v0（并行开发的对接面）

> 执行者1 **实现前可微调**；若有调整：**先更新本文件（v1）并公告到房间**，工作者按最新版接线。
> 字段名可改，但「能力点」不许少。

**1) `GET /api/interaction/feed?limit=40`**（R18 互动运营区；R23 复用）
```json
{ "ok": true,
  "replies":  [{"id":1,"user":"昵称","comment":"用户原话","reply":"我们回了什么","mode":"auto|manual","at":"ISO","note":"笔记标题"}],
  "incoming": [{"user":"昵称","text":"留言","at":"ISO","note":"笔记标题"}] }
```
来源：`comments` 表（replied=1）+ 最新未回留言/通知；空数组 = 空态。

**2) `GET /api/analytics/insight`**（R21 整体解读 + 高潜方向建议）
```json
{ "ok": true, "generated_at":"ISO",
  "summary": "整体一段话解读",
  "highlights": ["…"],
  "suggestions": [{"direction":"方向名","reason":"为什么","action":"具体做什么"}] }
```
来源：创作者中心 30 天数据 + metrics + contents；DeepSeek 生成；无 Key / 样本不足 → `{ok:false, reason}`，前端空态。

**3) `GET /api/notes/performance?limit=30`**（R21 逐篇数据）
```json
{ "ok": true, "items": [{"title":"…","date":"YYYY-MM-DD","views":123,"likes":0,"collects":0,"comments":0,
  "missing": ["views"]}] }
```
平台给不了的字段 → `null` + 记入 `missing`，**不许用 0 冒充**。

## 三、执行者1（后端线）队列与验收

> 顺序 = 优先级。**T-A\* 最先**（工作者第一批在等）。

- **T-A1** 契约 1) + 3) 实现。验收：真实数据 curl 出数（replies 能读到已有回复记录；incoming 有则显示、无则空数组）。
- **T-A2** 契约 2) AI 解读。验收：真实生成一段解读（DeepSeek 已就绪）；无数据走 `ok:false`。
- **T-B（R19 后端）**
  - 生成模式：无生成内容 → 7 天；已有 → 1 篇（`POST /api/generate` 支持 `mode:auto|seven|single`）
  - `withImages:true` → 生成后逐篇自动配图（复用现有生图链路，提示词从内容扩写；**实测只跑 1 篇验证**，别一次烧 7 篇）
  - 生成结果可指定排期日（写入 publish_tasks 或 day_index+scheduled_at，实现后公告）
  - 收藏字段（`favorite`，轻量迁移加列）+ `PATCH /api/contents/:id` 白名单**显式**支持 `favorite`
  - 7 天自动删除：`source='generated'` 且 draft 且**未排期**且**未收藏** 且 created_at 超 7 天 → 删除（挂进现有调度）。验收：**造一条 7 天前的测试数据 → 跑一轮 → 被删；再造成收藏状态 → 活着**
- **T-C（R20 后端）**
  - 设置键 `auto_send`（关=到点需**人工确认**；开=**直接发送**）——关时到点任务进"待确认"状态并暴露给前端；新增 `POST /api/publish/tasks/:id/confirm`
  - `publish_protect`（默认开）：关=跳过五项预检直接进入发送；**"提前 15 分钟预检"的时机保留**
  - `actual_sent_at` 真实发送时间落库并在 tasks 列表返回
  - tasks 列表**带内容快照字段**（title/body/images/tags）供展开查看 + 手机预览；支持 `?from&to`（或返回全量由前端分组，实现后公告）
  - 验收：安全半必做（排到明天 → tick → 仍 pending；关自动发送 → 到点转"待确认"不直发）；**`run`/`now` 这类真发布接口不许自测乱调**
- **T-D（R22 后端）**：三板块字段改造（人物设定=人设+语气 / 目标人群 / 核心要求=卖点+转化目标+内容要求，见 Q3）+ **完整运营策略**（怎么做 / 多长时间什么目标 / 分阶段+选题）落库 + `/api/outline/chat`（**带上下文记忆**：对话历史存表、注入最近 N 轮；AI 返回 JSON `{reply, strategy_patch}`，**服务端真实落库修改策略**）+ `GET /api/outline/chat` 历史。验收：多轮对话第 2 轮能引用第 1 轮；对话后策略真实变化；`/api/generate/context` 能看到策略进入参考系。
- **T-E（R23 后端）**：评论自动回复总开关接入（R14 轮询尊重该开关）；互动动态复用契约 1)；私信无后端（前端只放跳转入口）。
- **T-F（R24 后端）**：资料库表（文档元数据 + 解析全文）+ 上传端点（docx/pdf/txt/md 解析——优先复用本机 Python 库，缺则 pip 装；docx 也可 zip+xml 零依赖解析）+ 自动转知识条目 + **`matchKnowledge` 接入资料库**（回复必须能引用到文档内容）。验收：上传一份真实文档 → match-test 命中 → 回复内容来自文档。

## 附录 B · 后端防坑四条

1. `node:sqlite` **不接受数组/对象绑定** → 写库前 `JSON.stringify`
2. `PATCH /api/contents/:id` 白名单是写死的 key 循环 → **新字段必须显式加**，否则静默忽略
3. MCP 连续快请求会限流 → 关键词间 ≥3.5s；抓 0 条先 sleep 25s 重试，别改代码
4. 改 `server/**` 不重启 = 改了不生效（会用旧代码反复误判"没生效"）
